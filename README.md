# spid-test

Консольный замер скорости скачивания. Скрипт десять раз подряд обращается к указанному адресу, каждый раз дожидается полного тела ответа и печатает среднее время, общий объём и скорость.

Дополнительные пакеты не нужны: используется встроенный `fetch` из Node.js. Настройки читаются из окружения и необязательного файла `.env`.

## Требования

Node.js 18 или новее.

```bash
node -v
```

## Запуск

```bash
node start.js <url>
```

Пример с тяжёлым файлом:

```bash
node start.js https://proof.ovh.net/files/10Mb.dat
```

Тот же запуск через npm:

```bash
npm start -- https://proof.ovh.net/files/10Mb.dat
```

Адрес должен начинаться с `http://` или `https://`. Если аргумент не передан или адрес некорректный, скрипт завершается с кодом 1 и короткой подсказкой.

Скопируйте `.env.example` в `.env`, если нужно поменять число запросов, таймаут, уровень логов или `User-Agent`. Переменные, уже заданные в системе, файл не перезаписывает. `REQUEST_COUNT` ограничен диапазоном 1–100, таймаут одного запроса — 1–600000 мс.

Логи пишутся в stderr и не смешиваются с отчётом. Уровни: `silent`, `error`, `info`, `debug`. При `debug` к неожиданной ошибке добавляется стек. В обычном режиме наружу уходит сообщение об ошибке, без стека.

## Что печатается

Для каждого из десяти запросов — размер тела, длительность и скорость этого запроса. Затем итог:

- среднее время одного запроса;
- общий объём десяти ответов;
- скорость скачивания за весь прогон.

Пример итога:

```text
Среднее время запроса: 840 мс
Общий объём: 9.54 МиБ (10000000 байт)
Скорость скачивания: 1.14 МиБ/с
```

## Единицы

| Величина | Единица | Как считается |
| --- | --- | --- |
| Время | миллисекунды (мс) | от вызова `fetch` до полного чтения тела ответа, включая установку соединения |
| Объём | мебибайт (МиБ) | байты тела ответа. 1 МиБ = 1 048 576 байт. Заголовки HTTP в объём не входят |
| Скорость | МиБ/с | общий объём в байтах ÷ суммарное время всех запросов в секундах ÷ 1 048 576 |

Среднее время — сумма десяти длительностей, делённая на 10.

Скорость всего прогона считается по сумме байт и сумме времени, а не как среднее десяти отдельных скоростей. Так один короткий ответ не перевешивает длинную загрузку.

## Как устроен замер

- Запросы идут строго по очереди: следующий начинается только после того, как тело предыдущего ответа прочитано целиком.
- Заголовок `Accept-Encoding: identity` просит сервер отдать тело без gzip и brotli, чтобы посчитанный размер совпадал с размером ответа.
- Редиректы (`301`, `302`, `307`, `308`) следуют автоматически. В объём входит только итоговое тело, не промежуточные ответы.
- Один запрос ждёт не дольше 120 секунд. Если ответа нет, скрипт останавливается и скорость не печатает: неполный прогон в среднее не попадает.
- Ошибка сети или ответ со статусом не 2xx тоже останавливают замер.
- Тело читается потоком и в память целиком не складывается: для скорости нужен только размер.
- Кэш ответа отключён (`cache: no-store`). Повторный запрос к тому же адресу должен измерять сеть, а не сохранённую копию.
- Логин и пароль в адресе (`https://user:password@host/...`) уходят в запрос, но в отчёт и лог попадает адрес без них.
