# spid-test

Консольный замер скорости скачивания. Скрипт десять раз подряд обращается к указанному адресу, каждый раз дожидается полного тела ответа и печатает среднее время, общий объём и скорость.

Дополнительные пакеты не нужны: запрос делает `node:http` / `node:https`. Настройки читаются из окружения и необязательного файла `.env`.

## Требования

Node.js 18 или новее.

```bash
node -v
```

## Запуск

```bash
node start.js <url>
```

Пример с тяжёлым файлом:

```bash
node start.js https://proof.ovh.net/files/10Mb.dat
```

Тот же запуск через npm:

```bash
npm start -- https://proof.ovh.net/files/10Mb.dat
```

Адрес должен начинаться с `http://` или `https://`. Если аргумент не передан или адрес некорректный, скрипт завершается с кодом 1 и короткой подсказкой.

Скопируйте `.env.example` в `.env`, если нужно поменять число запросов, таймаут, уровень логов, `User-Agent`, прогрев или режим соединения. Переменные, уже заданные в системе, файл не перезаписывает. `REQUEST_COUNT` ограничен диапазоном 1–100, таймаут одного запроса — 1–600000 мс. `WARMUP` и `FRESH_CONNECTION` принимают только `0` или `1`.

Логи пишутся в stderr и не смешиваются с отчётом. Уровни: `silent`, `error`, `info`, `debug`. При `debug` к неожиданной ошибке добавляется стек. В обычном режиме наружу уходит сообщение об ошибке, без стека.

## Что печатается

Сначала шапка: адрес, число зачётных запросов, включён ли прогрев и переиспользуется ли соединение. Если прогрев включён, его строка идёт первой и в итог не входит. Для каждого зачётного запроса — размер тела, полное время, время до первого байта, время чтения тела и скорость этого запроса. Затем итог только по зачётным запросам:

- среднее, минимум, максимум и медиана полного времени;
- среднее время до первого байта и среднее время тела;
- общий объём;
- скорость скачивания за весь прогон.

Пример:

```text
Адрес: https://proof.ovh.net/files/10Mb.dat
Запросов: 10, один за другим
Прогрев: 1 запрос, в итог не входит
Соединение: повторно используется

прогрев. 9.54 МиБ, 900 мс, до первого байта 180 мс, тело 720 мс, 10.60 МиБ/с
01. 9.54 МиБ, 820 мс, до первого байта 40 мс, тело 780 мс, 11.63 МиБ/с

Среднее время запроса: 840 мс
Минимум: 800 мс
Максимум: 910 мс
Медиана: 835 мс
Среднее до первого байта: 40 мс
Среднее время тела: 800 мс
Общий объём: 95.37 МиБ (100000000 байт)
Скорость скачивания: 11.36 МиБ/с
```

## Единицы

| Величина | Единица | Как считается |
| --- | --- | --- |
| Время | миллисекунды (мс) | от отправки запроса до полного чтения итогового тела. Редиректы входят в это время |
| До первого байта | миллисекунды (мс) | от отправки запроса до заголовков итогового ответа |
| Тело | миллисекунды (мс) | от заголовков итогового ответа до конца тела |
| Объём | мебибайт (МиБ) | байты тела ответа. 1 МиБ = 1 048 576 байт. Заголовки HTTP в объём не входят |
| Скорость | МиБ/с | общий объём в байтах ÷ суммарное полное время зачётных запросов в секундах ÷ 1 048 576 |
| Разброс | миллисекунды (мс) | минимум, максимум и медиана полного времени зачётных запросов. При чётном числе медиана — среднее двух центральных |

Среднее время — сумма длительностей зачётных запросов, делённая на их число. Прогрев в сумму не входит.

Скорость всего прогона считается по сумме байт и сумме полного времени, а не как среднее отдельных скоростей. Так один короткий ответ не перевешивает длинную загрузку. Время до первого байта и время тела в формулу скорости не подставляются: они показывают, где прошло время.

## Как устроен замер

- Запросы идут строго по очереди: следующий начинается только после того, как тело предыдущего ответа прочитано целиком.
- По умолчанию перед зачётом выполняется один прогрев. Он скачивает тот же адрес, печатается отдельной строкой и не входит ни в среднее, ни в объём, ни в скорость. Соединение после него остаётся открытым: у клиента один сокет на адрес, и зачётные запросы идут по нему, без повторного рукопожатия.
- `FRESH_CONNECTION=1` закрывает соединение после каждого запроса. Тогда каждый зачётный замер снова включает установку соединения. Прогрев при этом по-прежнему не входит в итог.
- Заголовок `Accept-Encoding: identity` просит сервер отдать тело без gzip и brotli. Если в ответе всё же есть `Content-Encoding` кроме `identity`, замер останавливается: иначе в объём попал бы размер после распаковки и скорость была бы завышена.
- Редиректы (`301`, `302`, `303`, `307`, `308`) следуют автоматически, не больше 20. В объём входит только итоговое тело, не промежуточные ответы. Время включает все прыжки.
- Один запрос вместе с редиректами ждёт не дольше 120 секунд. Если ответа нет, скрипт останавливается и скорость не печатает: неполный прогон в среднее не попадает.
- Ошибка сети или ответ со статусом не 2xx тоже останавливают замер.
- Тело читается потоком и в память целиком не складывается: для скорости нужен только размер.
- Отдельного HTTP-кэша нет: каждый запуск заново ходит в сеть. Повторные зачётные запросы могут переиспользовать только уже открытое соединение, не сохранённое тело.
- Логин и пароль в адресе (`https://user:password@host/...`) уходят в запрос, но в отчёт и лог попадает адрес без них.

Проверка локально:

```bash
npm test
```
